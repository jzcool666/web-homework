## 2 每阶段交付格式

实现前确认对应Spec版本；实现后记录文件与Spec关系、迁移变化、接口变化、测试命令、结果和剩余问题。每个功能分支关联一个Spec；跨模块的集成修复说明涉及的多个Spec。

先完成正常流程，再处理权限、空数据、并发、时间边界和页面状态；这些边界是验收内容，不作为可无限延期的“优化”。功能完成后同步README和检查记录，不能只更新代码。

## 3 内容准备

第一批内容服务于D3课堂演示：模6计数器5→0、4位寄存器右移、D触发器有效沿、JK翻转。每例至少配一段讲解、一道预测题、一个实验和明确状态序列。D5后以触发器、计数器、寄存器、状态转换的先修关系维护知识图谱种子（经无环校验），并为识别辅助提供一份规定格式的计数器状态表样例。素材总量按精简口径扩充到6单元、12知识点、36题、4实验、16问答条目；计数器和寄存器各有可验证实验。

题目审核检查初态、时钟沿、复位、位序、正确答案和解析是否一致。若素材不可靠，减少装饰与无关内容，不能以增加题数代替内容正确性。

## 4 风险与控制

| 风险 | 控制 |
| --- | --- |
| 功能范围大导致课堂主流程迟迟不可用 | D3形成可演示版本，配套和智能逐步补齐；不同时扩展可选模块 |
| 仿真视觉与逻辑不同步 | 所有图表来自一个状态对象，前后端共享规格测试向量 |
| 学生断网或重复点击 | 保存回执、幂等约束、明确最后同步时间 |
| 统计和预警样本不足 | null/insufficient与样本量明确，不制造成绩或结论 |
| SQLite课堂负载不足 | 短事务、3秒轮询、一次规定规模测试；未实测不承诺更大规模 |
| 题库约束无解 | 生成前检查数量，求解后验约束，区分无解和超时 |
| 交付环境无法运行 | 清洁目录安装和无外网核心流程验收，锁定依赖 |

## 5 课程提交准备

六份主文档与代码最终一致，规格和检查结果可追溯。Gitea同步代码历史及docs材料；班级、组号、最终报告模板在提交前补齐。源码包保留锁文件、迁移、种子与使用说明，排除密钥、数据库、依赖目录、缓存和与课程交付无关的工作文件。
