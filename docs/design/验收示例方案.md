# 验收示例方案

2026-10-04，关联 [Issue #66](https://github.com/jzcool666/web-homework/issues/66)。本方案先于实现冻结；演示初始化属于交付工具，不新增业务接口、迁移或教学模块。实现及运行证据另记验收报告。

## 1 使用场景

老师首次查看系统时，可以直接切换教师和学生账号，看到完整的课堂与学习流程。演示记录是明确标注的模拟数据，不代表真实出勤、成绩、学习掌握程度或实际课堂使用。真实班级资料和用户口令不得写入示例。

## 2 数据范围

| 对象 | 初始样例 |
| --- | --- |
| 账号与班级 | 1 演示管理员、2 演示教师、A 班 12 名学生、B 班 3 名学生；姓名和班名均有“演示/模拟”标识，学号使用 99000001—99000015 |
| 课程、问答与实验 | 复用现有种子：六章节、12 知识点、16 问答、D/JK/模6/移位寄存器四实验、四接线/电路任务 |
| 题库 | 36 题，每知识点单选/多选/判断各一题；难度覆盖 1—3，解析说明相关时序规则；使用既有题型、选项和答案校验 |
| 备课与预习 | 一份含知识点、资源、题目与实验四类引用的备课单，发布给 A 班；公开题目快照仅题干，不泄露答案 |
| 随堂测 | 一份待发布草稿、一份初次导入时进行中的测评、一份已结束且公开反馈的测评；冻结题目与12人名单 |
| 作答与错题 | 已结束测评中有正确、错误、漏答、白卷及未开始；学生01保留首次答错与后来重练答对的历史 |
| 考勤 | 三次已结算模拟任务，覆盖出勤、迟到、缺勤、批准请假；教师仍可通过正常页面新建真实过程演示任务 |
| 学习与实验记录 | 不同完成比例、收藏、资源事件，以及实验先错后对/仅错/通过三种情况；成绩和预期状态由既有逻辑计算 |
| 课堂演示 | 一份进行中计数器演示，保留固定配置快照，预测初始隐藏 |
| 智能功能 | 数据满足至少10人、三因素齐全且至少三种向量，供教师在页面实际生成预警/分组；推荐、问答、组卷和图谱沿用正式接口，不灌入虚构结果 |

进行中测评截止设为首次导入时间后一天，预习截止为后七天。重复导入不延长截止、不重开课堂、不覆盖用户新操作；过期后由教师正常创建下一次演示。

## 3 初始化边界

命令 `flask --app app:create_app seed-demo --confirm-demo-database`，口令从环境变量 `DEMO_PASSWORD` 读取，要求10—128字符，不回显或记录口令。所有演示账号首次使用相同的临时演示口令，演示库不用于真实个人数据。

只允许空库首次创建，或本命令完整创建过的演示库重复调用。发现非演示账号、保留账号角色/学号不匹配或不完整的演示账号集合，拒绝操作且不修改库。账号命名为 `demo_admin`、`demo_teacher_a/b`、`demo_student_01`—`15`。明确确认标志和账号检查同时满足才运行。

初始化只提交一个事务；复用种子函数与领域判分/仿真函数，失败时回滚。重复调用直接报告已有示例，不追加历史、不恢复被用户改变的记录、不重置口令。无需新增持久化标记表；使用完整保留账号集合和固定演示备课单作为初始化检查。删除了该备课单或账号的库不会静默补建，应另建空库重新演示。

样例历史以首次初始化时间为基准，回溯最近几天；入班时间早于全部样例记录。模拟历史通过服务端生成并校验，不能写成真实学生曾在这些时间操作过。

## 4 验收标准

1. 空库迁移后初始化成功，全部关联、唯一约束和名单有效。
2. 36题通过既有校验，测评快照、总分和错题历史由相同判分函数计算；改题不回写快照。
3. 重复运行前后全表快照一致；用户改口令/成绩/课堂版本后也不被重置。
4. 缺确认、缺口令、非演示库及不完整保留账号集合全部拒绝，库未改变；故障注入后无部分创建。
5. 教师和学生通过真实浏览器使用示例，课堂、讲评、统计、实验、错题与推荐能加载；他班权限仍隔离。
6. 教师通过既有预警接口实际生成分组，确认至少10名三因素齐全学生以及三种向量；不预填假算法结果。
7. 前后端适当回归和构建通过。测试证据注明隔离库、模拟数据和代码版本。

完整教学示例与文件素材按已验证的模型和端口规范准备；模板、标准示例和故意错误示例明确区分，不把演示样例误称学生作业或验收成绩。
