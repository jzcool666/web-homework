# 实验箱与电路测评使用说明

本功能提供四项实验：D触发器、同步模6计数器、四位双向寄存器、两位Gray状态机。实验箱引脚采用TI手册的DIP顶视图：缺口朝上，左侧从1脚向下编号，右侧从下向上编号。电源为+5V/GND，芯片行为按低有效异步清零和上升沿采样。这里是数字逻辑教学模拟，不模拟模拟电压、接触电阻或烧毁芯片。

## 学生接线

1. 登录学生账号，在有效班级下打开“实验箱与电路测评”，选择“开始／继续接线”。“新建练习”会建立独立过程，已有记录保留。
2. 关电时先点一个箱端子或芯片脚，再点另一端完成连线；也可展开“按端点名称接线”。导线颜色用于区分接线，端点颜色表示电平；导线交叉不代表电气连接。点击导线或列表里的“删除”可拆线；撤销、重做均留下新的过程记录。
3. 连接芯片的VCC和GND。未使用的功能单元可以留空；使用某单元的输出时，应接齐它的输入、时钟及控制脚。活动时序单元的CLK须直接接实验箱CLK。
4. 开电后先清零：CLR_N保持0，D实验的PRE_N设为1；再将CLR_N设为1。PRE_N和CLR_N不能同时为0。上电的X表示未知状态，Z表示未连接或关电，不能当成0。
5. 用开关改变输入，切换时钟0→1产生上升沿、1→0回到低电平。计数器的EN=0保持；寄存器的S1S0=00保持、01右移、10左移、11并行装载。位序按任务页说明。
6. 操作成功后自动保存，刷新可恢复。断线时点击“重试保存操作”，系统重复确认同一动作。出现版本冲突时读取服务器的最新过程，不覆盖另一窗口的操作。
7. 点击“提交接线测评”。服务器另用测试输入检查最终接线，显示得分、通过计分点和首错。结构有问题时先修线，不生成成绩。以后继续改线不会改写已有成绩和过程快照。

最多256条线、512个操作。达到过程上限后新建练习；“清空实验箱”保留已收到的过程，不能用它绕过上限。窄屏中实验箱内部可横向滚动，也可用端点列表完成连线。

连线较多时，悬停或键盘聚焦一条导线可高亮它及两端，其余线淡化。实验箱下方“追踪导线”列表可固定高亮，点击“取消追踪”恢复；只读记录中也可点击导线追踪。可编辑且关电时，点击导线仍是拆线操作。走线会自动错开，交叉处的留白不表示电气连接。

## 上传Logisim电路

1. 下载任务的端口模板。安装[Logisim-evolution 5.0.0](https://github.com/logisim-evolution/logisim-evolution/releases/tag/v5.0.0)，在桌面软件里完成电路。模板只有main及指定Pin，不包含答案。
2. 保持入口名称`main`，输入输出Pin的名称、方向、位宽与任务表完全一致。可以改变连线布局，也可以使用支持的器件实现等价功能。
3. 保存为5.0.0的`.circ`，选择班级、文件并上传。其他版本需先用5.0.0打开后另存；仅改XML的source字段不保证兼容。
4. 文件最多2MiB、16个电路、512个器件、2048段线。不支持递归子电路、外部库/JAR、HDL、RAM/ROM、图片、网络或文件组件。实际器件与属性白名单由服务端校验，上传页展示支持范围。
5. 上传成功后显示“等待测评／正在测评”，页面自动刷新，也可从历史继续查看。每人最多2个未完成任务，两次上传至少间隔10秒。
6. 正常完成显示分数和首错输入、实际、期望输出。测评服务中断、超时或输出异常显示“测评失败”，成绩为空；使用“重新上传”建立新记录。原文件可从结果页鉴权下载。

有限用例全部通过表示本次测试通过，不等于对所有输入序列作形式化证明。系统不按XML文字相似度给分。

## 教师查看与演示

教师在自己的班级打开任务，可新建演示并打开投屏；投屏只显示电路状态，控制在原窗口完成。“实验记录与统计”可筛选班级、任务、方式和状态；打开学生的接线记录可逐步回放，文件记录可下载原文件。教师对学生过程只读。汇总只计当前有效在册学生，接线与文件分开统计；参与、通过人数去重，完成尝试按次计，队列和故障单列，无参与的通过率为“—”。退班学生仍可读本人历史。

## 管理员部署

沿用README的Python依赖、Node构建、数据库和账号初始化步骤。数据库先升级到`0012_spec018`，建立已发布知识点后执行：

```powershell
# 工作目录：backend
python -m flask --app app:create_app db upgrade
python -m flask --app app:create_app seed-labs
```

接线实验不依赖Java。文件测评需要Java21或以上及官方5.0.0的`logisim-evolution-5.0.0-all.jar`，下载后用`Get-FileHash -Algorithm SHA256`核对：

```text
6b368e894742c04cc83aa9830f869bcab0190ede4df43ad6fecdb89b3a23a41c
```

在应用和worker两端设置相同的`DATABASE_URL`、`UPLOAD_DIR`及运行环境，同时配置两个绝对路径。下面的路径由部署者按本机位置填写：

```powershell
$env:LAB_JAVA = 'C:\运行工具\jdk-21\bin\java.exe'
$env:LAB_JAR = 'C:\运行工具\logisim-evolution-5.0.0-all.jar'
# 在独立终端运行；同一上传目录只允许一个worker
python -m flask --app app:create_app lab-worker
```

worker启动会验证Java、JAR哈希及真实引擎自检，成功后输出“worker已就绪”。另一个终端按README用Waitress启动Web应用。worker未配置或心跳超过15秒时上传返回可读503，接线与原课堂仍可用。每个文件任务在独立临时目录运行，15秒超时、256MiB堆、256KiB输出上限；停止worker后的未完成任务在重启、租约过期时保留为失败，可重新上传。

已验证Windows11登录会话下的Waitress及独立CLI进程；当前不承诺Windows无人登录服务账号或无显示Linux运行。不要加`-Djava.awt.headless=true`，已观察到该模式失败。Java/JAR放在仓库外，安装时下载，课堂测评读取本机文件。

备份仍使用`scripts/backup.py`，包含三张实验表与原始附件，排除`lab-runtime`中的运行锁和心跳。恢复前停止Web与worker，恢复数据库和附件后重新启动；不要直接在有新提交的正式环境执行downgrade。恢复核对增加`lab_tasks`、`lab_sessions`、`lab_attempts`。证据见[实验扩展验收报告](testing/实验扩展验收报告.md)。
