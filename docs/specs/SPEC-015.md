# SPEC-015 个性化复习推荐

版本：设计基线 1.0，2026-09-28（2026-10-02 实现时补充字段与排序口径）。状态：已实现，执行结果见[报告](../testing/SPEC-015-执行报告.md)。模块对应：孙之宁。关联需求：FR-17。前置依赖：SPEC-006、SPEC-009、SPEC-014。

## 1 范围

为学生排序知识点与练习入口，解释原因。非目标：给教师推送个人画像或声称推荐能提高成绩。

## 2 接口契约

E065 GET /me/recommendations {limit?} → items含kind/resource_id/knowledge_id/title/score/reasons。

接口完整字段、角色缩写、状态码和公共错误定义见 [APIC](../../APIC.md)。所有写操作按公共规则校验会话、CSRF和对象权限；列表/导出同样不能越权。匿名401、角色拒绝403、跨班对象404、字段错误422、状态/版本冲突409；本模块特有错误以 APIC 为准。

APIC 只给出了 E065 条目的字段名，实现后把口径写死如下（属口径明确，未增删字段）：

- `kind=knowledge`：`resource_id` 与 `knowledge_id` 都是该知识点的 ID，`title` 是知识点标题。
- `kind=question`：`resource_id` 是题目 ID，`knowledge_id` 是它所属的知识点，`title` 是题干；**不含**选项、答案与解析。
- `score`：0—100 的个性化优先度，按可用信号加权归一化后四舍五入两位小数；**没有任何可用信号时为 `null`**，表示这条只是基础路径，不能读作 0 分「已掌握」。
- `reasons`：至少一条、全部来自实际可用信号；不写不存在的错误次数或未发生的实验失败。
- `limit` 默认 5；非整数是格式错误 400 INVALID_REQUEST，整数但超出 1—10 是字段错误 422 VALIDATION_ERROR（沿用 APIC 第 1 节的分工）。

## 3 数据结构

learning_progress、已公开submission_answers、experiment_attempts、knowledge_edges、questions；首版不新建推荐缓存表。

各字段类型、可空性、唯一键、外键、索引和删除策略见 [DBD](../../DBD.md)。涉及新表及索引时以迁移实现，不运行时自动建表覆盖已有数据。

## 4 业务规则

1. 按知识点聚合已公开首答错误率e、明确未完成记录p（未完成1/完成0）、实验失败比例x。NumPy按0.5/0.3/0.2对可用项归一化，缺失项不当失败。「已公开」沿用 SPEC-009/010 的口径：只有 `feedback_released=1` 的测评（自练恒为已公开）里的首答才计入 e——学生自己还看不到对错的测评，不能拿来当推荐依据。首答取该题全历史最早一次已提交作答，与 SPEC-010 一致。
2. 只使用本人记录；无任何信号时按章节顺序推荐基础知识点，理由为入门路径，不显示虚构个性化得分。
3. 有薄弱知识点时优先返回其未完成先修知识点，再返回该知识点与未做练习；已完成且首答正确率≥.8且实验通过的内容降序或排除。
4. 推荐不返回题目答案；本人所在班级中已发布但尚未公开反馈的班级测评所用题排除，结束不等于公开，已结束但未公开反馈的同样排除，直到反馈公开，避免旁路泄题。最多返回limit条，不足时不重复凑数。
5. 同分按章节顺序和ID排序。每条理由来自实际可用因素，不写不存在的错误次数。

6. 组装顺序（实现后固定）：薄弱知识点按分值降序（同分按章节顺序、章内 sort_order、ID）逐个展开——先给它的**明确未完成**先修，再给它自己，再给它尚未答对的练习；薄弱项讲完后再按章节顺序补基础路径条目，这些条目 `score=null`、理由为「按章节顺序的基础路径」。已掌握的知识点（完成 + 首答正确率 ≥ .8 + 无未通过实验）在两步里都被排除。

7. 「未完成先修」只认**明确记录**（`learning_progress.completed=0`）。毫无进度记录的先修不算「未完成」——否则任何薄弱知识点都会被一串从未打开过的先修挤到后面，学生看不到自己真正错在哪里。这与第 1 条「缺失项不当失败」是同一口径。

8. 练习候选：已发布、按题目 ID 升序，且本人**尚未答对**（从未作答或首答错误）的题；已按第 4 条排除避免旁路泄题的题。
